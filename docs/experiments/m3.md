# M3 experiments: user controls

Run after the M2 checklist (`docs/experiments/m2.md`), with the same install and log
commands. Record the date, iOS version, CI run and outcome for each.

## E13: blocked log

1. With protection on, browse a site with ads, then open the Activity tab.
2. Pass: domain blocks (orange) and, with HTTPS filtering on, request blocks (red) appear
   within a few seconds, newest first; repeated blocks show "N times"; search and the
   Domains/Requests filter work; Clear empties the list.
3. With HTTPS filtering on, open a host that only the DNS lists block (see M2 E10 step 5).
   Pass: it appears as a domain block (orange), not a request block.

## E14: allowlist from the log

1. Tap a blocked domain and choose "Never block <domain>". Protection restarts.
2. Pass: Settings, Allowed sites lists `*.<domain>`; the domain no longer appears in the log
   when you revisit the site. Remove it again from Allowed sites.
3. On a request block that shows "on <site>", choose "Allow everything on <site>". Pass:
   request blocks on that site's pages stop.

Result:

## E15: never filtered and learned pins

1. Settings, Never filtered: add `*.example.com`; try an invalid entry such as `exa mple`.
   Pass: the valid one is saved, the invalid one shows "Not a valid host pattern".
2. Settings, Learned certificate pins: note any hosts, swipe one to forget it. Pass: it
   disappears with protection on and with protection off. Besides apps that pin their
   certificates, this list also holds sites whose server certificate the proxy could not
   verify (for example a server that omits its intermediate certificate): the first request
   to such a site fails once, then it is passed through and works on reload.

Result:

## E16: lists and my rules

1. Settings, Filter lists: switch off EasyPrivacy, tap Apply changes now. Pass: it applies
   in seconds (from the cache, no download) and the rule count on Home drops.
2. Add a custom list over https (for example a hosts file). Pass: Apply downloads only that
   list. An http:// URL cannot be added. Then add one whose URL returns 404. Pass: Settings,
   Filter lists shows it as a warning and "some lists could not be downloaded"; returning to
   the app does not download everything again (the retry waits an hour). Remove it.
3. My rules: add `||example.com^`, Save. Pass: status "Active"; example.com fails to load
   while protection is on. Remove the rule and Save again.
4. Airplane mode on, change a toggle, Apply. Pass: it still applies from the cache.

## E17: automatic updates

1. Leave the app in the background for more than a day. (Or set the date forward by two
   days, open the app, check step 2, then set the date back to automatic and open the app
   once more: it updates again, so the stored time is not left in the future. With HTTPS
   filtering on, the downloads and any sites opened in between go through the proxy: after
   the date is back, those sites still load and Settings, Learned certificate pins shows no
   new hosts.)
2. Pass: Settings, Filter lists shows a new "Updated" time without tapping Update. Background
   refresh depends on iOS; opening the app after 24 hours also triggers the update.
