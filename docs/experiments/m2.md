# M2 experiments: first testable build

Commands run from the repo root on the Linux workstation, with the iPhone connected over USB.
Record the date, iOS version, CI run and outcome for each.

## Install

1. `tooling/scripts/fetch-ipa.sh <branch>` (the branch the build came from).
2. `tooling/scripts/install.sh`.
3. In a second terminal: `tooling/scripts/device.sh syslog live --label -e 'dev\.tollgate\.'` to watch the app, the tunnel and the Rust core together.

## E8: DNS blocking

1. Open Tollgate. The filter lists download and compile on first launch; the Filter lists row
   shows the rule and domain counts. Pass: roughly 110,000 request rules and 150,000 or more
   blocked domains, no error.
2. Tap Turn on and allow the VPN configuration. Status shows Protected.
3. In Safari open a page known for heavy advertising (for example a news site). Pass: the
   Activity section shows "Domains blocked" increasing and "DNS queries" increasing; pages
   load normally.
4. Toggle Airplane mode on and off. Pass: protection comes back on by itself (on-demand).

## E9: certificate install and trust

1. Tap Install profile. Safari opens and asks to allow the download. Allow it.
2. Settings, Profile Downloaded, Install (enter passcode).
3. Settings, General, About, Certificate Trust Settings, turn on "Tollgate Root CA".
4. Back in Tollgate, the Certificate row shows Trusted. If Safari did not offer the download,
   use "Share profile instead", save to Files, open it from Files, then continue at step 2.

## E10 (spec E4): HTTPS filtering

1. Turn on HTTPS filtering (the tunnel restarts).
2. Browse the same sites in Safari. Pass: "Requests blocked" and "Connections filtered"
   increase; pages still load; the log shows no stream of TLS errors.
3. Open an Apple app (App Store) and a banking app. Pass: both work; "Connections passed
   through" increases.
4. Check the "Certificate rejections" counter after using a few third-party apps. Any app
   that pins certificates should appear here and then keep working (it is passed through
   after two rejections).

## E11 (spec E5, E7): what bypasses the proxy

1. With HTTPS filtering on, use the phone normally for 15 minutes (Safari, a couple of
   apps with ads).
2. Compare "Connections filtered" plus "Connections passed through" with "DNS queries".
   Many DNS queries with few proxied connections means apps are not using the system proxy,
   which decides whether the userspace network stack (phase 2) is needed.
