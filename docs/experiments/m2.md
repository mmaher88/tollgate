# M2 experiments: first testable build

Commands run from the repo root on the Linux workstation, with the iPhone connected over USB.
Record the date, iOS version, CI run and outcome for each.

## Install

1. Build the tip of the branch under test: `gh workflow run ios.yml --repo mmaher88/tollgate --ref <branch>`,
   then wait for it with `gh run watch --repo mmaher88/tollgate` (pushing to a branch
   without an open pull request does not start a build).
2. `tooling/scripts/fetch-ipa.sh <branch>`. It only takes the build of the branch tip and
   fails when that build is missing, still running or red. It prints the run number (`#N`),
   the run id and URL, and the commit (also in `build/ipa/BUILD_INFO`). Record the run
   number and commit with each result.
3. `tooling/scripts/install.sh`. In the app, Diagnostics, Build shows "N (short commit)";
   check that it matches the run number and short commit printed in step 2.
4. In a second terminal: `tooling/scripts/device.sh syslog live --label -e 'dev\.tollgate\.'` to watch the app, the tunnel and the Rust core together.

## E8: DNS blocking

1. Open Tollgate. The filter lists download and compile on first launch; the Filter lists row
   shows the rule and domain counts. Pass: roughly 110,000 request rules and 150,000 or more
   blocked domains, no error.
2. Tap Turn on and allow the VPN configuration. Status shows Protected.
3. In Safari open a page known for heavy advertising (for example a news site). Pass: the
   Activity section shows "Domains blocked" increasing and "DNS queries" increasing; pages
   load normally.
4. Toggle Airplane mode on and off. Pass: protection comes back on by itself (on-demand).
5. Open a few large sites served through CDNs (their names often have long CNAME chains or
   many addresses, so the DNS answer can be bigger than one classic 512-byte reply). Pass:
   they load. A site that fails with "server not found" only while protection is on points
   at a DNS answer that did not fit; note the name.
6. Browse a few sites on Wi-Fi, then turn Wi-Fi off in Control Center and, within a few
   seconds, open two or three sites you have not visited yet. Pass: they load without a
   pause or "server not found"; the log shows "network path changed" and "dropping DoH
   connections".

## E10 (spec E4): HTTPS filtering

1. Turn on HTTPS filtering (the tunnel restarts).
2. Browse the same sites in Safari. Pass: "Requests blocked" and "Connections filtered"
   increase; pages still load; the log shows no stream of TLS errors.
3. Open an Apple app (App Store) and a banking app. Pass: both work; "Connections passed
   through" increases.
4. Check the "Certificate rejections" counter after using a few third-party apps. Any app
   that pins certificates should appear here and then keep working (it is passed through
   after two rejections).
5. Pick a host that is on the AdGuard DNS filter but not on EasyList, EasyPrivacy or AdGuard
   Mobile Ads (or add `||<host>^` to My rules and save). With HTTPS filtering on, open
   `https://<that host>/` in Safari, and use an app that talks to a DNS-listed host while
   being passed through (a pinned app from step 4). Pass: both fail to load, "Domains
   blocked" increases and the host appears in the Activity log as a domain block. Ordinary
   pages still load, never with "server not found".
6. The proxy looks upstream names up over DNS over HTTPS itself and uses the system
   resolver only when that fails. Repeat step 2 on cellular (some carriers are IPv6-only
   with NAT64). Pass: pages load as on Wi-Fi.
7. Browse a few sites on Wi-Fi, lock the phone, turn Wi-Fi off in Control Center (or walk
   out of range) and wait a minute, then unlock and reload the same sites. Pass: they load
   within a few seconds, with no missing images; the log shows "dropping pooled upstream
   connections" and "dropping DoH connections". Then the quick variant: with the phone
   unlocked, browse on Wi-Fi, turn Wi-Fi off in Control Center and reload the sites within
   a few seconds. Pass: nothing stalls or fails with "server not found". Also with an app
   whose host is passed through (the App Store, WhatsApp Web in Safari), a page with a
   live WebSocket (a web chat) or a page with a live feed that updates without reloading
   (live scores, a live blog): turn Wi-Fi off while it is open. Pass: it reconnects
   within a few seconds on cellular instead of hanging for a minute.
8. Sites that cannot be reached. With HTTPS filtering on, open
   `https://tollgate-no-such-host.example/` in Safari. Pass: Safari shows its own error
   page (for example "Safari can't find the server" or "can't connect to the server"), as
   with HTTPS filtering off, never an empty white page; the log shows
   `upstream tollgate-no-such-host.example: unreachable`. Then type `neverssl.com` (a site
   that only serves `http://`) in the address bar. Pass: it loads as with HTTPS filtering
   off.

## E11 (spec E5, E7): what bypasses the proxy

1. With HTTPS filtering on, use the phone normally for 15 minutes (Safari, a couple of
   apps with ads).
2. Compare "Connections filtered" plus "Connections passed through" with "DNS queries".
   Many DNS queries with few proxied connections means apps are not using the system proxy,
   which decides whether the userspace network stack (phase 2) is needed.
